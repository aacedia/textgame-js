# textgame-js

Текстовая игра на HTML5 + JavaScript в духе QSP-плееров.

Можно запустить в браузере: [Live Demo](https://aacedia.github.io/textgame-js/)

## Что это

Игрок перемещается между локациями (Квартира, Улица, Университет, Магазин),
выбирает действия, собирает предметы, тратит время и деньги. Есть день/время,
инвентарь, расписания заведений, сохранение в localStorage.

## Запуск

Открыть `index.html` в браузере.

## Архитектура

Слои, снизу вверх:

    data → rules → game → ui

- **data** — только контент. `window.GAME_DATA`.
- **rules** — чистые функции без побочных эффектов. `window.Rules`.
- **save** — обёртка над localStorage. `window.Save`.
- **ui** — рендер и DOM. Не знает про состояние и правила. `window.UI`.
- **game** — состояние, view-модель, диспетчеры. `window.Game`.

Каждый модуль регистрирует методы через `Object.assign(window.X, {...})`,
поэтому порядок подключения в `index.html` критичен:

    data → rules → save → ui-* (ядро → соседи → ui.js) → game-* (state → viewmodel → actions → commands → game.js)

UI не читает `state` и не знает про правила. Логика не трогает DOM.
Единственная точка встречи состояния и представления — `game-viewmodel.js`.

## Ключевые понятия

Три независимых потока данных:
- `state` — локация, инвентарь, флаги, переменные, uiTab, controlsOpen, logOpen, lastVariant.
- `logEntries` — «История событий»: только переходы. Лимит 10, новые сверху.
- `infoEntries` — «Информация»: результат последнего осмысленного действия.
  Лимит 6, заменяется целиком.

Элемент `infoEntries` — `{ kind: "text", text }` или `{ kind: "image", src, alt?, caption? }`.

`Rules.applyEffect` — чистый редьюсер: принимает `state`, возвращает новый `state`
и массив сообщений `{ kind: "move" | "info", text }`. `move` идёт в «Историю»,
`info` — в «Информацию».

У действия может быть поле `variants` — массив вариантов исхода. `Rules.pickVariant`
фильтрует их по `condition` и выбирает случайный. Текст и картинка берутся сначала
из варианта, потом из действия. Эффекты применяются и от действия, и от варианта.

### Случайные события и повторы

По умолчанию один и тот же вариант не выпадает два раза подряд: `pickVariant`
исключает прошлый выбор для этого действия (`state.lastVariant[actionId]`), если
есть альтернативы. Это не удаляет вариант из пула — он снова доступен после
другого исхода.

Если нужно разрешить повтор — на вариант ставится `repeatable: true`:

    {
      repeatable: true,
      text: "Мимо проезжает автобус…",
      image: "assets/images/locations/street-scene-bus.jpg"
    }

Поведение по умолчанию — «без повтора подряд». Флаг `repeatable` нужен только
там, где повтор должен быть разрешён явно.

`hiddenWhen` на действии скрывает его из списка, пока условие выполнено (в отличие
от `condition`, который делает кнопку серой, но не убирает).

## Контент

Всё содержимое — в `js/data/data.js`: локации, предметы, персонаж, стартовое
состояние, граф переходов (`links`).

Условия и эффекты — декларативные, описаны в `rules.js`. Полный список типов
условий и эффектов — в шапке `rules.js`. Валидация ссылок в данных выполняется
при старте (`js/data/data-validation.js`) и пишет предупреждения в консоль.
